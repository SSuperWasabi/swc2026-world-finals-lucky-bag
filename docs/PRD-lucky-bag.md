## 1. 목적

SWC2026 월드 결선(2026-11-14 토, 서울 KBS 아레나) 컴투스 스토어 팝업에서 럭키백을 산 고객이 **산 수량만큼 A/B/C 유형을 뽑는** iPad 앱이다.

- **최우선 목표 [결정]:** 럭키백 300개 전량 판매(A·B·C 각 100개).
- **A/B/C [결정]:** 구성만 다르고 가치는 거의 같다. 그래서 등급 연출 없이 세 유형을 같은 무게로 보여준다.
- **성공 기준:**
  1. 고객에게는 짧고 신나는 뽑기 경험.
  2. 직원에게는 수량·결과·재고가 절대 헷갈리지 않는 화면.
  3. 하루 동안 끊김 없이 오프라인으로 돈다.

### 하지 않는 것 (범위 밖)
- 경품 추첨(럭키백 1개당 1회)은 이 앱과 무관하다 **[결정]**. 화면·기록·안내 어디에도 넣지 않는다.
- POS 연동은 하지 않는다. 직원이 수량을 손으로 넣는다 **[결정]**.
- 결제 처리, 영수증 출력, 온라인 서버는 없다.

### 실패로 보는 것 (기능이 돌아가도)
- 재고와 실물이 어긋나거나, 새로 고침·실수로 결과가 다시 뽑힌다.
- 남은 재고보다 많은 결과를 만들어 낸다.
- 화면 끝내기(초기화)가 판매 기록이나 재고를 지운다.
- 행사장에서 iPad가 버벅이거나 영상이 끊긴다.

## 3. 한 구매의 흐름

### 3-0. 화면 흐름 **[결정 11-09 Jason: 기존 럭키드로우 WF와 같은 순서]**
1. **메인 루핑 화면** (대기)
2. **트랜지션** — 기존 럭키드로우 앱 전환 영상 그대로
3. **선택 화면** — 직원이 구매 수량 입력
4. **선택 오픈** — 카드가 나오고 [TAP TO OPEN]
5. **결과 확인** — 직원이 [지급 완료]를 누르면 트랜지션 후 1로. 자동으로 넘어가지 않는다 **[결정: 7초 자동 복귀 대신 직원 확인]**
   - 4개 이상(여러 묶음)이면 5에서 [다음 묶음] → 4(다음 묶음)로, 마지막 묶음에서만 [지급 완료] **[Leo 결정]**
   - **결과 확인 스위치 [결정 11-09 Jason: on/off로]** 관리자 → 설정. 켜기(기본) = 위처럼 직원 버튼. 끄기 = 버튼 없이 결과 화면 탭 또는 7초 뒤 자동으로 다음 묶음/메인. 다 열린 직후 1초 동안의 탭은 무시한다(연타로 결과를 못 보고 넘어가는 것 방지). 구매 시작 때 설정이 고정된다.
6. 1부터 반복
- 구매 요약 화면은 없앴다. 결과 화면 아래에 이번 구매 누적(A·B·C)을 보여 준다 **[Leo 결정]**.
- 트랜지션은 1→3, 3→4, 5→1에서 재생한다. 묶음 사이에는 재생하지 않는다 **[Leo 결정]**.
- 공개 방식 기본값은 "동시에(TAP TO OPEN)"로 바꿨다. "한 장씩"·"한 개씩" 스위치는 관리자에 그대로 둔다 **[Leo 결정]**.

### 3-1. 기본 흐름 (2개 구매, A와 C가 나온 예)
1. 고객이 "2개 살게요" → 직원이 POS에서 2개 결제.
2. **직원 화면:** 직원이 iPad에 수량 2를 넣고 [뽑기 시작]을 누른다.
   - 앱은 남은 재고가 2개 이상인지 먼저 검사한다. 모자라면 시작을 막는다(5절).
3. **뽑기 화면:** 카드 2장이 휘리릭 돌며 등장한다(가챠 연출).
   - 고객이 화면을 눌러 뒤집으면 A·C 결과가 나온다. 공개 방식은 설정 1을 따른다.
4. **결과 유지:** 직원이 영수증 두 장에 결과를 도장으로 찍는 동안 결과 화면을 그대로 둔다. 시간이 지나도 자동으로 넘어가지 않는다.
5. **직원 확인:** 직원이 [지급 완료]를 누르면 구매 요약(A 1 · C 1)을 보여주고, [다음 고객]을 누르면 대기 화면으로 간다.

### 3-2. 여러 개 구매 — 추첨 단위는 스위치로 고른다 **[결정 11-09]**
현장 상황에 따라 관리자 설정 3(4절)에서 켜고 끈다.

- **한 개씩:** 카드 1장씩 뽑는다. 10개 구매라면 1장 뽑기 → 결과 → [다음 뽑기]를 10번 반복한다.
  - 한 장 한 장 연출을 크게 보여줄 수 있다. 줄이 길면 느리다.
- **한꺼번에:** 수량을 넣으면 한 번에 최대 3장씩 결과를 낸다 **[결정: 한 번에 최대 3장]**.
  - 10개라면 3·3·3·1로 나눈다. 묶음마다 3-1의 3~4단계를 반복한다.
- 두 방식 모두 화면 아래에 진행 표시("2 / 10" 또는 "BATCH 2 / 4")와 이번 구매의 누적 결과(A 3 · B 2 · C 1)를 보여준다.
- 뽑기 사이에는 직원이 [다음 뽑기] 또는 [다음 묶음]을 누른다(영수증 기록을 마친 뒤).
- 마지막 뽑기가 끝나야 [지급 완료] → 구매 요약 → [다음 고객]이 나온다.
- 한꺼번에 추첨에서 1개·2개만 남은 묶음은 그 수량만큼만 카드가 나온다 **[결정]**.

## 4. 앱 설정 (관리자 → 설정, 모두 스위치) **[결정]**

### 설정 1 — 공개 방식 (한꺼번에 추첨일 때만)
- **한꺼번에:** 묶음의 카드가 모두 등장한 뒤 [OPEN] 한 번에 동시에 뒤집힌다.
- **한 장씩:** 카드가 모두 등장한 뒤 고객이 원하는 카드를 하나씩 눌러 뒤집는다. 다 뒤집어야 다음 단계 버튼이 나온다.
- 기본값 **[Leo 제안]:** 한 장씩. 뽑는 재미를 살리고, 3장 이하라 시간 부담이 작다.

### 설정 2 — 중복 줄이기 (한 구매 안)
- **끄기:** 카드마다 남은 재고 비율대로 무작위로 고른다(재고가 많은 유형이 더 잘 나옴).
- **켜기:** 같은 구매 안에서 지금까지 가장 적게 나온 유형을 우선한다. 그 유형들 중에서는 재고 비율대로 고른다.
  - 예: 3개 구매 + 재고 넉넉 → 반드시 A·B·C 하나씩. 4~6개 → 각 유형이 1~2개씩.
  - **범위 [Leo 제안]:** 묶음이 아니라 구매 건 전체다. 10개 구매의 두 번째 묶음도 앞 묶음 결과를 반영한다.
- **재고가 우선이다 [결정: 운영안 그대로].** 품절 유형은 빼고 남은 유형으로 겹침을 줄인다. 켜기는 "서로 다른 세 유형"을 약속하는 기능이 아니다.
- 기본값 **[Leo 제안]:** 켜기. 300개 중 각 100개라 켜도 재고가 고르게 줄어 완판에 유리하다.

## 5. 재고·기록 규칙

- **결과는 뽑는 순간 확정해 저장한다 [Leo 제안].**
  - 묶음을 시작하면 앱이 결과를 먼저 정해 재고를 줄이고 기록에 쓴 뒤 연출을 튼다.
  - 연출 중 새로 고침이나 앱 재시작이 생겨도 다시 뽑지 않고 같은 결과로 이어서 보여준다.
  - "결과에 따라 지급 → 재고 반영" **[결정]**과 같은 뜻이다.
- **재고 부족 차단:** 입력 수량이 남은 전체 재고보다 많으면 [뽑기 시작]을 막고 "남은 럭키백 N개" 안내를 띄운다. 결과를 임의로 만들지 않는다 **[결정]**.
- **초기화 ≠ 삭제:** [다음 고객]은 현재 고객 화면만 끝낸다. 재고와 기록을 지우는 일은 관리자에서만 하고, PIN과 재확인을 거친다.
- **입력 실수:**
  - 뽑기 전: 직원 화면에서 수량을 고치면 된다.
  - 뽑은 뒤: 관리자 → 기록에서 해당 구매를 [취소]하면 재고를 되돌리고 기록에 "취소"로 남긴다. 기록을 지우지는 않는다.
- **실물과 다를 때:** 관리자 → 재고에서 유형별 수량을 직접 고친다. 고친 내역도 기록에 남긴다.
- **기록 항목:** 구매 번호, 시각, 수량, 묶음별 결과, 설정 상태(추첨 단위·공개 방식·중복 줄이기), 취소·재고 수정 내역.
  - CSV 내보내기와 전체 백업 파일(기존 `.kuji` 방식)을 지원한다.
- **장애 대비:** 앱 밖에서 종이 추첨과 수기 재고표로 대신한다(운영안). 복구 뒤 관리자 재고 수정으로 맞춘다.

### 6-3. 프리뷰의 움직임
- **0.0초:** 배경과 타이틀은 첫 프레임부터 있고, 엠블럼은 0.1초부터 그려지며 나타난다.
- **가운데 방패:** 0.1초부터 약 0.35초 동안 흐릿하게 시작해 살짝 위로 떠오르며 또렷해진다.
- **왼쪽 방패:** 0.5초 시작, 0.9초 완료. **오른쪽 방패:** 0.7초 시작, 1.1초 완료.
  - 0.2초 간격의 차례 등장이고, 끝으로 갈수록 느려진다(ease-out).
- **1.1초 이후:** 방패는 멈춰 있다.
  - 배경 광선은 계속 흐른다.
  - 엠블럼은 2~3초마다 깜빡이는 글리치 효과가 반복된다.
- 정확한 키값은 AE 원본의 같은 이름 컴프에서 다시 뽑는다(6-5).

### 6-4. 카드 연출 — 앱에서 가장 중요한 요소 **[결정 11-09]**
목표: 뽑는 순간 "와" 소리가 나오는 가챠 느낌. Jason이 준 레퍼런스(인스타그램 릴스 "Make a card reveal feel epic", 영상 사본 `.claude/uploads/…124427.mp4`)의 5단계 공식을 OAP 보라 톤으로 옮긴다.

**레퍼런스 분석 (84초, 같은 카드를 밋밋한 버전 → 5단계 적용 버전으로 비교):**
| 단계 | 레퍼런스에서 하는 일 | 효과 |
| --- | --- | --- |
| 1 빌드업 | 카드가 받침대 위로 천천히 떠오르고 테두리 빛이 점점 강해진다(빛 세기 = 희귀도) | 기대감 |
| 2 느린 뒤집기 | 옆면(90°)에서 잠깐 멈춰 얇은 빛줄기만 보이다가 휙 끝까지 넘어간다 | 긴장 → 해소 |
| 3 빛 폭발 | 흰 섬광 + 방사형 광선 + 받침대 위로 빛 고리가 퍼져 나간다 | 터지는 순간 |
| 4 호일 광택 | 카드가 살짝 기울며 무지개빛 광택이 앞면을 훑고 지나간다 | 고급스러움 |
| 5 사운드 | 휙(뒤집기), 우르릉(빌드업), 쾅(폭발), 반짝(광택) | 체감 2배 |

**우리 앱의 카드 1장 공개 순서 [Leo 제안, 시간은 첫 구현 뒤 Jason과 조정]:**
1. **등장 (약 1.0초):** 카드 뒷면이 화면 밖에서 휘리릭 여러 바퀴(Y축 회전 2~3바퀴) 돌며 자리로 날아와 앉는다. 빛 꼬리와 반짝이가 따라온다.
   - 순서는 OAP처럼 가운데 → 왼쪽 → 오른쪽, 0.2초 간격.
   - 1장이면 가운데만, 2장이면 왼쪽·오른쪽 두 자리.
   - 자리에 앉은 뒤에는 위아래로 천천히 떠 있고, 카드 아래 바닥 빛 고리가 은은하게 숨 쉰다.
2. **빌드업 (누르면 시작, 약 0.8초):** 카드가 살짝 더 떠오르고 테두리 빛이 강해진다. 빛 입자가 카드로 모이고 낮은 울림 소리가 난다.
3. **느린 뒤집기 (약 0.6초):** 옆면까지 천천히 돌아 약 0.35초 멈춘다. 이때 세로 빛줄기만 보인다. 그다음 0.12초 만에 휙 앞면으로 넘어간다.
4. **빛 폭발 (약 0.7초):** 흰 섬광, 방사형 광선, 바닥 빛 고리가 퍼지고 빛 입자가 터진다. 쾅 소리.
5. **호일 광택 (약 1.0초 뒤 반복):** 카드가 살짝 기울며 무지개빛 광택이 앞면을 훑는다. 그 뒤에는 몇 초마다 한 번씩 은은하게 반복된다.

- **세 유형의 연출 크기는 똑같다** (가치가 같으므로). 빛 색만 유형별 강조색이다: A 분홍, B 보라, C 금색.
- "한꺼번에" 공개는 세 장이 0.15초 간격으로 2~5단계를 거의 동시에 겪는다. "한 장씩"은 누른 카드만 2~5단계를 겪는다.
- **구현 방식 [Leo 제안]:**
  - 카드의 회전·떠오름·기울기는 결과마다 앞면이 달라지므로 CSS 3D로 한다.
  - 섬광·광선·빛 고리·빛줄기·입자처럼 빛만 있는 효과는 AE에서 검은 배경 영상으로 렌더해 카드 위에 겹친다(스크린 합성, 빛만 남음). AE의 빛 질감을 그대로 쓰면서 iPad 부하가 낮다.
  - 효과음은 기존 앱 소리를 먼저 쓰고, 부족한 휙·쾅 소리는 새로 만든다.

### 6-4-1. 카드 디자인 **[결정 11-09: 힉스필드로 제작]**

## 7. 기술 구성

- **[Leo 제안]** 기존 럭키드로우 앱에서 이것만 가져온다:
  - PWA 껍데기(오프라인 캐시, 매니페스트), 관리자 진입·PIN, 저장 방식, 백업·복원, 테스트 도구.
- 쿠지·피규어 뽑기 화면(소환서 선택, 드래그 오픈, 상품 영상)은 쓰지 않는다. 뽑기 화면은 새로 만든다.
  - 뽑기 규칙 코드(`draw-engine.js`)도 4절 규칙으로 새로 쓴다(순수 함수 + 회귀 검사).
- **이름 분리:** 같은 `ssuperwasabi.github.io` 주소를 쓰므로, 한 iPad에서 럭키드로우 앱과 섞이지 않게 모두 나눈다.
  - 저장 키 `swc2026-world-finals-lucky-bag.*`, 미디어 DB, 캐시 `swc2026-world-finals-lucky-bag-vN`, PWA id, 앱 이름 "SWC Lucky Bag", 버전 `swc-lb-vN`.
- **원격:** 기존 럭키드로우 저장소는 `luckydraw` 원격으로 이름을 바꾸고 푸시를 막아 두었다. 새 비공개 저장소를 `origin`으로 연결했다(2026-11-09).
- **배포·iPad 테스트:** 이름 분리를 마치기 전에는 푸시하지 않는다.
  - 비공개 저장소의 GitHub Pages는 유료 요금제에서만 켜진다. 푸시 뒤 Pages가 켜지는지 확인한다.
  - 안 켜지면 대안 1: 테스트 기간만 PC 로컬 서버를 Cloudflare 터널(이 PC에 설치돼 있음)로 HTTPS 주소를 만들어 iPad에서 연다.
  - 대안 2: 행사 직전에 공개로 바꿔 Pages로 배포한다. 홈 화면 앱은 고정 주소가 필요하므로 최종본은 Pages 쪽을 권한다.
